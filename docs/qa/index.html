Воспроизведение

Из корня репозитория выполните команды ниже. Они создают временную копию с отдельной SQLite и используют интерпретатор из .venv проекта. Данные из исходной базы не нужны. Стенд слушает только 127.0.0.1. Chrome должен быть установлен для проекта Playwright с channel=chrome.

Подготовить тестовую копию и запустить сервер

QA_PROJECT="$(pwd -P)"
QA_KIT="$QA_PROJECT/docs/qa"
QA_COPY="$(mktemp -d)"
export QA_COPY QA_KIT
export QA_PYTHON="$QA_PROJECT/.venv/bin/python"

rsync -a --exclude='.git' --exclude='.venv' --exclude='db.sqlite3*' \
  --exclude='.pytest_cache' --exclude='.coverage' --exclude='__pycache__' \
  --exclude='.cache' --exclude='.matplotlib' --exclude='/docs/qa/' "$QA_PROJECT/" "$QA_COPY/"
cd "$QA_COPY"
touch .qa-scratch
mkdir -p reports
"$QA_PYTHON" manage.py migrate --noinput
"$QA_PYTHON" manage.py seed_data
"$QA_PYTHON" "$QA_KIT/stand/fixtures.py" api
printf 'QA_COPY=%s\n' "$QA_COPY"
DJANGO_DEBUG=False "$QA_PYTHON" manage.py runserver 127.0.0.1:8765 --noreload --insecure

Оставьте сервер запущенным. Во второй вкладке задайте QA_COPY по строке, которую напечатал стенд, и укажите те же QA_KIT и QA_PYTHON. Экспортируйте QA_PYTHON перед запуском Playwright. Системные кейсы и проверка безопасности могут запускаться отдельно. Не запускайте несколько пишущих прогонов одновременно на одной SQLite.

Материалы предыдущих работ находятся в спецификации ЛР1, диаграмме состояний и отчёте ЛР2.

Запустить ЛР3 и проверки безопасности

cd "$QA_COPY"
mkdir -p "$QA_COPY/reports"
"$QA_PYTHON" "$QA_KIT/lab3/system_cases.py" "$QA_COPY/reports"
"$QA_PYTHON" "$QA_KIT/lab4/security_checks.py"   "$QA_COPY/reports/security.json" http://127.0.0.1:8765
"$QA_PYTHON" -m pytest --cov=shop --cov-report=term-missing

Запустить UI-тесты и проверки совместимости

cd "$QA_KIT/lab4/ui"
npm ci
npx playwright install firefox webkit
QA_PROJECT_DIR="$QA_COPY" npm test
npm run report

Если нужны только функциональные UI-тесты, используйте npm run test:ui. Для матрицы браузеров доступна команда npm run test:compat. HTML-отчёт Playwright создаётся даже при провале ожиданий.

Импортировать и запустить Postman

Импортируйте коллекцию Postman v2.1, запустите папки целиком от 01 до 06 и очистите cookie для тестового хоста перед стартом. Автопереходы отключены в настройках запросов. Переменная baseUrl по умолчанию указывает на 127.0.0.1:8765. Коллекция меняет тестовые данные и уменьшает остаток контрольной детали на 3 при успешном прогоне. Для чистого повтора используйте новую копию SQLite.

postman collection run "$QA_KIT/lab4/postman/AutoParts.postman_collection.json"   --ignore-redirects --reporters cli,json   --reporter-json-export "$QA_COPY/reports/postman.json"

В итоговых прогонах FAIL соответствуют зарегистрированным дефектам. Полный необработанный отчёт Postman из повторного запуска содержит тестовые cookie и тела ответов. Для сдачи используйте компактный отчёт из комплекта.
