AutoParts · контрольная спецификация

Контрольная выдержка из docs/requirements.md, разделы 3 и 4, ревизия 305c4bf. Сохранены исходные идентификаторы и формулировки.

Функциональные требования

IDТребованиеСвязь с UC
FR-01Каталог /parts/ показывает только активные товары (is_active = True).UC-1
FR-02Поиск по подстроке в названии, типе и производителе без учета регистра; сотрудник дополнительно ищет по артикулу.UC-1
FR-03Фильтр по типу товара (?type=<id>); некорректное значение фильтра игнорируется.UC-1
FR-04Сортировка: по названию (по умолчанию), цене ↑/↓, количеству ↑/↓; неизвестный вариант → по названию.UC-1
FR-05Карточка товара показывает название, цену, остаток и до 3 похожих товаров того же типа; удаленный товар недоступен (404).UC-1
FR-06Добавление в корзину: количество от 1 до min(99, остаток); товар с нулевым остатком не добавляется.UC-2
FR-07В корзине можно увеличить/уменьшить количество (при уменьшении с 1 позиция удаляется), удалить позицию, очистить корзину; итог пересчитывается.UC-2
FR-08Удаленные или деактивированные товары автоматически исчезают из корзины.UC-2
FR-09Оформление заказа доступно только вошедшему пользователю с профилем клиента и непустой корзиной; иначе — перенаправление на вход / заполнение профиля / каталог.UC-3
FR-10Проверка формы заказа: телефон +375 (XX) XXX-XX-XX, корректный email, адрес обязателен для курьера и почты, дата получения не в прошлом, согласие с офертой; при оплате картой — 16 цифр номера, держатель, срок, CVC из 3 цифр.UC-3
FR-11Промокод (без учета регистра) дает скидку в %, если он активен и сегодня в периоде его действия; неизвестный или просроченный отклоняется с сообщением.UC-3
FR-12При оплате картой заказ получает статус «Оплачен», фиксируется время оплаты, остаток уменьшается, записываются продажи, корзина очищается.UC-3
FR-13При оплате через ЕРИП или по счету заказ создается со статусом «Ожидает оплаты», товар не списывается; клиент может оплатить заказ из профиля. Если товара уже не хватает, оплата отклоняется.UC-3
FR-14Заказ со статусом «Ожидает оплаты» можно отменить; оплаченный или отмененный заказ нельзя ни оплатить, ни отменить повторно.UC-4
FR-15Заказ и его страница подтверждения доступны только владельцу (чужому пользователю — 404).UC-3, UC-4
FR-16Регистрация создает пользователя и профиль клиента; возраст ≥ 18 лет, email уникален, телефон в формате РБ.UC-5
FR-17Отзыв может оставить только вошедший пользователь, оценка 1–5.UC-6
FR-18Сотрудник создает, редактирует и удаляет товары; удаление «мягкое» (товар скрывается, запись остается). Клиенту эти действия недоступны.UC-7
FR-19Статистика (сумма, среднее, медиана, мода, популярный тип) и график выручки доступны только сотрудникам.UC-8
FR-20/api/parts/ возвращает JSON каталога только вошедшим пользователям; артикул (sku) — только сотрудникам.—
FR-21Страница /external-apis/ показывает факт из catfact.ninja и IP из ipify.org; при ошибке сервиса — запасной текст.UC-9
FR-22Форма обратной связи проверяет имя, email, телефон, сообщение (10–600 символов); для темы «Подбор по VIN» обязателен VIN из 17 символов; год выпуска — от 1980 до следующего календарного года; принятая заявка сохраняется для менеджера.—

Нефункциональные требования

IDТипТребование
NFR-01ПроизводительностьСтраница каталога с демо-данными отвечает локально не дольше 1 с.
NFR-02БезопасностьВсе изменяющие действия (корзина, оплата, отмена, удаление) выполняются только POST-запросом с CSRF-токеном; GET → 405. Пароли хранятся в виде хеша. Перенаправления выполняются только внутри сайта.
NFR-03НадежностьЗапрос к внешнему API ограничен таймаутом 2 с; при ошибке страница отвечает 200 с запасным значением. Оплата заказа атомарна: либо списаны все позиции, либо ни одна.
NFR-04Устойчивость к вводуНа некорректные параметры URL и форм система отвечает сообщением об ошибке или кодом 4xx, но не ошибкой 500.
NFR-05ПереносимостьПриложение запускается локально (SQLite) и в Docker (PostgreSQL) без изменения кода — только переменными окружения.
NFR-06УдобствоИнтерфейс на русском; разметка страниц проходит валидатор W3C без ошибок; ошибки формы показываются над формой.
NFR-07СопровождаемостьПокрытие кода автотестами — не ниже 70% (без миграций и настроек).
