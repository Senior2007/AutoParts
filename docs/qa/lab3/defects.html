BUG-1 · Нечисловой тип ломает каталог

Требование
FR-03, NFR-04
Статус
Открыт
Важность
Средняя
Срочность
Высокая
Симптом
Ошибка HTTP 500
Ожидаемый результат
Каталог отвечает 200, неизвестный фильтр игнорируется.
Фактический результат
С фильтром type=abc сервер отвечает 500.

Повторено в Django Test Client и Postman на SQLite.

QA-08 · Режим DEBUG показывает серверную трассировку

Требование
NFR-02, NFR-04
Статус
Открыт
Важность
Высокая
Срочность
Высокая
Симптом
В ответе раскрывается техническая информация
Ожидаемый результат
Внешний ответ на ошибку не содержит трассировку и пути.
Фактический результат
При DEBUG=True ответ 500 содержит traceback, абсолютные пути и техническую область Django. При DEBUG=False эти маркеры отсутствуют.
Шаги воспроизведения
  1. Запустить только отдельную копию со штатным DEBUG=True.
  2. Вызвать ошибку в каталоге на тестовых данных.
  3. Сравнить признаки ответа при DEBUG=True и DEBUG=False.
Воспроизводимость
На изолированном стенде 500 при DEBUG=True дал диагностические маркеры; при DEBUG=False их не было.
Обход
Для доступного пользователям стенда установить DJANGO_DEBUG=False.
Доказательства
SEC-04 и SEC-05 · Маркеры ответа

QA-09 · Вход, оплата и отмена не оставляют событий аудита

Требование
NFR-02, FR-12, FR-14
Статус
Открыт
Важность
Средняя
Срочность
Средняя
Симптом
У операций нет прикладной записи для диагностики
Ожидаемый результат
Журнал фиксирует вход, оплату и отмену с результатом операции.
Фактический результат
Операции выполняются, но событий аудита для них нет. Записи заявки, отказов интеграции и HTTP-ошибок присутствуют.
Шаги воспроизведения
  1. Включить сбор shop и django.request.
  2. Войти синтетическим клиентом.
  3. Оплатить свой тестовый заказ и отменить второй.
  4. Сверить итоговые состояния и прикладной журнал.
Воспроизводимость
Три операции из трёх успешны, три события из трёх отсутствуют на уровне INFO.
Обход
Сопоставлять статус и отметку оплаты в БД с access-логом. Полноценное событие входа этим не восстанавливается.
Доказательства
SEC-06 и SEC-07 · Журнал проверки

QA-10 · Каталог выходит за ширину страницы

Требование
NFR-06, FR-01
Статус
Открыт
Важность
Средняя
Срочность
Средняя
Симптом
Горизонтальная прокрутка всей страницы
Ожидаемый результат
При уменьшении окна и увеличении масштаба элементы помещаются в доступную ширину или данные прокручиваются внутри таблицы.
Фактический результат
На десктопе 1024 → 1071 px и 768 → 807 px. На мобильном профиле 393 → 575 px при CSS zoom 200%.
Шаги воспроизведения
  1. Открыть каталог.
  2. Выставить viewport 1024 или 768 CSS px.
  3. Сравнить scrollWidth и clientWidth. Повторить в мобильном профиле при CSS zoom 200%.
Воспроизводимость
На двух прогонах desktop-профилей Chrome, Firefox и WebKit; мобильное переполнение подтверждено в финальном прогоне.
Обход
На десктопе использовать 1440 px или мобильную ширину при масштабе 100%; при необходимости прокрутить страницу.
Доказательства
Матрица размеров · Скриншот Chrome 1024 px · Скриншот эмуляции 200%

QA-11 · Внешняя карта сообщает ошибку в Console Firefox

Требование
NFR-06
Статус
Открыт
Важность
Низкая
Срочность
Низкая
Симптом
Консольное сообщение из вложенного iframe
Ожидаемый результат
При открытии контактов консоль не содержит ошибок стороннего виджета.
Фактический результат
Firefox регистрирует сообщение Error из скрипта embed OpenStreetMap. Локальный маршрут отвечает 200, локальных 404 и исключений приложения не обнаружено.
Шаги воспроизведения
  1. Открыть Firefox на странице контактов.
  2. Дождаться загрузки ресурсов карты.
  3. Посмотреть Console и источник сообщения.
Воспроизводимость
Зафиксировано в двух прогонах Firefox на этом стенде. В Chrome, WebKit и Chrome mobile в итоговом прогоне не зафиксировано.
Обход
Использовать текстовый адрес из контактов или открыть карту отдельно.
Доказательства
Протокол Firefox · Сетевые и консольные события
